# أمان وكلاء الذكاء الاصطناعي وحماية التوجيهات (AI Agent Security Standards)

## 1. الحماية من هجمات حقن التوجيهات (Prompt Injection Defense)
- **حقن التوجيه المباشر (Direct Prompt Injection / Jailbreaking)**:
  - محاولات تجاوز الضوابط الأمنية عبر توجيهات خبيثة في مدخلات المستخدم تطالب النموذج بتجاهل التعليمات السابقة.
  - الدفاع: تطبيق طبقات تنقية وفصل دقيق بين تعليمات النظام الحاكمة (`System Instructions`) ومدخلات المستخدم المعاملة كبيانات غير موثوقة حصراً.
- **حقن التوجيه غير المباشر (Indirect Prompt Injection)**:
  - حقن نصوص خبيثة داخل صفحات ويب أو مستندات أو استجابات واجهات خارجية يقرأها النموذج أثناء أداء مهامه.
  - الدفاع: فحص وتنقية المحتوى المسترجع من المصادر الخارجية قبل تمريره للنموذج، والتحقق من السياق قبل تنفيذ أي استدعاء أدوات.

---

## 2. تقييد صلاحيات الأدوات وتنفيذ العمليات (Tool Sandboxing & Least Privilege)
- **عزل صلاحيات استدعاء الأدوات (Tool Calling Governance)**:
  - عدم منح النموذج صلاحيات تنفيذ أوامر نظام تشغيل عامة أو استعلامات قواعد بيانات مباشرة دون فحص وسيط.
  - إخضاع استدعاءات الأدوات الحساسة (تعديل ملفات، تنفيذ أوامر، استدعاء واجهات خارجية) لضوابط تفويض صارمة وموافقة صريحة عند تجاوز عتبات المخاطر.
- **منع تسريب البيانات عبر قنوات الذكاء الاصطناعي (AI Data Leakage)**:
  - حظر تمرير مفاتيح API أو الأسرار أو البيانات الحساسة (PII) داخل سياق المحادثة أو التوجيهات الموجهة لنماذج الذكاء الاصطناعي الخارجية.
  - تنقية الاستجابات الصادرة من النموذج للتأكد من خلوها من بيانات داخلية حساسة قبل عرضها.

---

## 3. التحقق من سلامة المخرجات الناتجة عن الذكاء الاصطناعي (Output Verification)
- معاملة أي شيفرة أو بيانات يولدها النموذج على أنها غير موثوقة (Untrusted Generated Content).
- فحص الشيفرات المولدة آلياً عبر أدوات الفحص الثابت (SAST) والتحقق الأمني قبل دمجها أو تنفيذها في بيئات التشغيل.
