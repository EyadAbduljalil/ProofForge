# الأنماط التصميمية الأمنية المعتمدة (Approved Security Design Patterns)

## 1. نمط حارس الملكية (Resource Ownership Guard Pattern)
- **الغرض**: منع ثغرات BOLA/IDOR والوصول غير المصرح به للموارد عبر فحص علاقة الملكية خادمياً.
- **التطبيق**: في كل استعلام استرجاع أو تعديل، يتم دمج معرف الكيان المالك المستخلص من جلسة التوثيق مع معلمات الاستعلام.

---

## 2. نمط التحقق عند البوابة (Gatekeeper / API Gateway Pattern)
- **الغرض**: مركزية التحقق من الهوية، فحص الترويسات الأمنية، وتطبيق محددات المعدل قبل وصول الطلب إلى الخدمات الداخلية.
- **التطبيق**: معالجة الطلبات الواردة في طبقة وسيطة موحدة تقوم بإنهاء اتصالات TLS والتحقق من رموز JWT ورفض الطلبات المشبوهة فوراً.

---

## 3. نمط الهروب السياقي الآمن (Contextual Sanitizer / Safe Sink Pattern)
- **الغرض**: منع كافة أشكال هجمات الحقن (XSS, SQLi, Command Injection).
- **التطبيق**: تغليف المخرجات والمدخلات بدوال تشفير وهروب محكمة بحسب وسيط التنفيذ النهائي، ومنع تمرير النصوص الخام مباشرة إلى الدوال التنفيذية الخطرة.

---

## 4. نمط التدوير التلقائي للأسرار (Automated Key Rotation Pattern)
- **الغرض**: تقليص نافذة الخطر الناتجة عن احتمال تسرب المفاتيح والرموز السرية.
- **التطبيق**: دعم التشفير والتحقق باستخدام مفتاحين متزامنين (Active Key & Retiring Key) لضمان انتقال سلس دون انقطاع للخدمة.
