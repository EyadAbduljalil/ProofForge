# إدارة الأسرار والمفاتيح الحساسة (Secrets Management Specification)

## 1. مبادئ عزل الأسرار وحظر التضمين المباشر (No Hardcoded Secrets)
- **المحظور الصارم المطلق**:
  - يُحظر تماماً كتابة أو حفظ أي مفتاح سري، رمز توثيق، كلمة مرور، شهادة خاصة، أو سلسلة اتصال بقاعدة البيانات داخل الشيفرة المصدرية أو ملفات التهيئة الخاضعة لنظام التحكم في الإصدار (Git).
- **التخزين والإمداد الآمن**:
  - تمرير الأسرار عبر متغيرات البيئة المشفرة (`Environment Variables`) أو عبر خزائن الأسرار السحابية والمحلية (HashiCorp Vault, AWS Secrets Manager, GCP Secret Manager, Azure Key Vault).
  - استخدام ملفات `.env` للتطوير المحلي فقط مع إضافتها وجوباً إلى `.gitignore`.

---

## 2. دورات حياة الأسرار وتدويرها (Secret Lifecycle & Rotation)
- **التدوير الدوري للأسرار (Periodic Key Rotation)**:
  - تدوير مفاتيح التشفير، كلمات المرور، وشهادات TLS بشكل تلقائي أو دوري (كل 90 يوماً كحد أقصى للأنظمة الحساسة).
  - دعم التعايش المزدوج للمفاتيح (Dual-Key Overlap) أثناء مرحلة التدوير لضمان استمرار الخدمة وفك تشفير البيانات السابقة بسلاسة.
- **إجراءات الاستجابة عند تسرب الأسرار (Secret Breach Response)**:
  - إبطال المفتاح المسرب فوراً واستبداله بمفتاح جديد مولد عشوائياً.
  - تدقيق سجلات الوصول في الفترة ما بين التسرب والإبطال لتحديد النطاق المتأثر.

---

## 3. الفحص الآلي للمستودع البرمجي (Automated Secret Scanning)
- تشغيل أدوات الفحص الآلي للكشف عن الأسرار (مثل `git-secrets`, `trufflehog`, `gitleaks`) قبل كل عملية Commit وأثناء مسار التكامل المستمر (CI/CD Pipeline).
- حظر دمج أي فرع يحتوي على سلاسل نصية تطابق أنماط التوكنات والمفاتيح السرية المعروفة.
