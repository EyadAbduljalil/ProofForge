# إدارة وتدقيق أمان التبعيات والمكتبات الخارجية (Dependency Security & Auditing)

## 1. الفحص الدوري وإدارة الثغرات المعروفة (Vulnerability Scanning)
- **التدقيق الآلي للتبعيات (Automated Dependency Auditing)**:
  - دمج أدوات التدقيق الأمني (مثل `npm audit`, `pip-audit`, `trivy`, `snyk`, `dependabot`, `OSV-Scanner`) في المسار اليومي للتطوير والتكامل المستمر.
  - حظر دمج ونشر أي شيفرة تحتوي على ثغرات مصنفة بدرجة خطورة حرجة (`CRITICAL`) أو عالية (`HIGH`) ما لم يتوفر استثناء أمني رسمي ومؤقت مع خطة تخفيف معتمدة.

---

## 2. معايير اختيار وتأهيل المكتبات البرمجية الجديدة
- **معايير القبول والتقييم الأمني**:
  - نشاط المشروع وتوفر تحديثات أمنية مستمرة وسجل زمني واضح للإصلاحات.
  - سمعة المطورين والمؤسسة الراعية وعدد التنزيلات والمساهمين.
  - وضوح الرخصة البرمجية (Open Source License Compliance) وتوافقها مع طبيعة المشروع.
  - خلو المكتبة من تبعيات متداخلة مفرطة أو نصوص برمجية غامضة ومبهمة (Obfuscated Code).

---

## 3. خطة الاستجابة للثغرات المكتشفة في الحزم (Patching & Remediation Workflow)
1. **الرصد والتصنيف**: تحديد مدى تأثر النظام الفعلي بالوظيفة المصابة بالثغرة داخل المكتبة (Reachability Analysis).
2. **الترقية والتحديث**: ترقية الحزمة إلى الإصدار المعالج مع تشغيل حزمة اختبارات الانحدار.
3. **التخفيف المؤقت**: في حال عدم توفر تحديث فوري، يتم تطبيق ضوابط تعويضية (مثل تعطيل الخاصية المصابة أو حظر المدخلات المسببة للاستغلال عبر طبقة الحوكمة الوسيطة).
