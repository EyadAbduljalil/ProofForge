# أمان إدارة الجلسات والتوكنات (Session & Token Security)

## 1. إدارة ملفات تعريف الارتباط للجلسة (Session Cookies)
عند استخدام ملفات تعريف الارتباط لإدارة الجلسات، يجب تطبيق الخصائص الأمنية التالية إلزامياً:
- **`HttpOnly`**: لمنع قراءة الكعكة بواسطة نصوص JavaScript وتخفيف أثر ثغرات XSS.
- **`Secure`**: لضمان إرسال الكعكة عبر اتصالات HTTPS المشفرة فقط.
- **`SameSite=Strict`** (أو `Lax` في تدفقات المصادقة التوجيهية): للحماية من هجمات تزوير الطلبات عبر المواقع (CSRF).
- **`Max-Age` / `Expires`**: تحديد مدة صلاحية زمنية ملائمة مع تجديد المعرف (Session Regeneration) عند تسجيل الدخول لمنع هجمات تثبيت الجلسة (Session Fixation).

---

## 2. معايير أمان رموز JSON Web Tokens (JWT)
عند اعتماد رموز JWT لتبادل الهوية غير المتزامن:
- **توقيع الرموز بخوارزميات غير متماظرة قوية**: استخدام `RS256` أو `EdDSA` والتحقق الصارم من حقل الخوارزمية في الترويسة لمنع هجمات `alg: none` أو تبديل الخوارزميات (Algorithm Confusion).
- **تحديد عمر قصير لرمز الوصول (Short-Lived Access Tokens)**: مدة صلاحية لا تتجاوز 15 دقيقة.
- **استخدام رموز التجديد المقيدة وتدويرها (Refresh Token Rotation)**:
  - إبطال رمز التجديد القديم فور إصدار رمز جديد.
  - إبطال كامل أسرة الرموز (Token Family Revocation) في حال استخدام رمز تجديد مستهلك سابقاً (مؤشر على سرقة الرمز).
- **تجنب تخزين الرموز الحساسة في `localStorage`**: تفضيل التخزين في كعكات `HttpOnly; Secure; SameSite=Strict`.

---

## 3. إبطال الجلسات والإنهاء الآمن (Session Revocation & Logout)
- إنهاء الجلسة من جانب الخادم بإلغاء سجل الجلسة أو إدراج الرمز في قائمة إبطال سريعة (Denylist/Revocation Table).
- توفير ميزة "تسجيل الخروج من جميع الأجهزة" عبر زيادة إصدار أمني للمستخدم (`token_version` أو `security_stamp`).
- إنهاء الجلسة تلقائياً بعد فترة خمول محددة (Idle Timeout) وفترة صلاحية قصوى مطلقة (Absolute Timeout).
