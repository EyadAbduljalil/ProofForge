# الأنماط الأمنية المضادة والمحظورات الصارمة (Security Anti-Patterns)

## 1. قائمة الأنماط الأمنية المضادة المحظورة

### أ) الأمان القائم على الغموض (Security through Obscurity)
- **الوصف**: الاعتماد على إخفاء الروابط أو استخدام مسارات سرية غير موثقة بدلاً من فرض آليات توثيق وتفويض حقيقية.
- **الخطر**: يستطيع المهاجمون اكتشاف المسارات عبر فحص الشيفرة، سجلات الشبكة، أو التخمين الآلي.

### ب) التفويض من جانب العميل فقط (Client-Side Only Authorization)
- **الوصف**: إخفاء زر التعديل أو شاشات الإدارة في واجهة المستخدم (UI) دون فحص الصلاحية في نقطة نهاية الخادم.
- **الخطر**: يمكن لأي مستخدم إرسال طلب HTTP مباشر لنقطة النهاية وتعديل البيانات بصلاحيات غير مصرح بها.

### ج) دمج النصوص في الاستعلامات والأوامر (String Concatenation in Queries/Commands)
- **الوصف**: بناء استعلامات SQL أو أوامر النظام بدمج مدخلات المستخدم نصياً.
- **الخطر**: يؤدي مباشرة إلى ثغرات الحقن الكاملة والسيطرة على الخادم وقواعد البيانات.

### د) تخزين الأسرار الصريحة في الشيفرة (Hardcoded Secrets in Source Code)
- **الوصف**: تضمين مفاتيح API، كلمات مرور، أو مفاتيح تشفير داخل ملفات المشروع البرمجية.
- **الخطر**: تسرب فوري للأسرار عند مشاركة المستودع أو تسريبه أو تخزينه في سجلات البناء.

### هـ) إعدادات CORS المتساهلة والخطيرة (Permissive Wildcard CORS with Credentials)
- **الوصف**: تفعيل `Access-Control-Allow-Origin: *` بالتزامن مع تفعيل الاعتمادات `Allow-Credentials: true`.
- **الخطر**: يسمح لأي موقع خبيث بقراءة بيانات المستخدم الحساسة واختراق جلسته.

### و) الثقة العمياء في بيانات العميل (Blind Trust in Client Input / Mass Assignment)
- **الوصف**: تمرير كائن الطلب كاملاً إلى دوال تحديث الكيانات في قاعدة البيانات دون تصفية.
- **الخطر**: تمكين المهاجم من ترقية حسابه إلى مدير (`role: admin`) أو تعديل حقول حساسة.
