# أمان واجهات برمجة التطبيقات (API Security Specification)

## 1. التوثيق والتفويض لنقاط النهاية (API Authentication & Authorization)
- يجب حماية جميع نقاط النهاية غير العامة بآليات توثيق قوية (OAuth 2.0 / OpenID Connect / Mutual TLS / Signed API Keys).
- توفير نطاقات صلاحية دقيقة (Fine-Grained Scopes) لكل مفتاح API لتقييد الصلاحيات وفق مبدأ الصلاحيات الدنيا.
- حظر تضمين مفاتيح API أو رموز الوصول في معلمات الاستعلام (`Query Parameters`) لأنها تُسجل في سجلات الخوادم والوكلاء؛ بل يجب تمريرها حصراً في ترويسة `Authorization`.

---

## 2. تحديد المعدل وإدارة الحصص (Rate Limiting & Quota Management)
- تطبيق محددات المعدل على مستويات متعددة:
  - مستوى عنوان IP للطلبات غير الموثقة لمنع هجمات الحرمان من الخدمة (DoS).
  - مستوى معرف المستخدم أو العميل المستأجر (User / Tenant ID) للطلبات الموثقة.
  - مستوى نقطة النهاية الفردية (خاصة نقاط تسجيل الدخول، استعادة كلمة المرور، وعمليات الدفع الحساسة).
- إرجاع ترويسات الاستجابة القياسية لإشعار العميل (`X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`, وترميز الحالة `429 Too Many Requests`).

---

## 3. حماية البيانات ومنع التسريب الزائد (Data Exposure & Filtering)
- **منع الإفراط في إرجاع البيانات (Excessive Data Exposure / Mass Assignment in Responses)**:
  - عدم إرجاع كائنات قاعدة البيانات الخام مباشرة إلى العميل.
  - استخدام كائنات عرض مخصصة (Response DTOs / Serializers) تتضمن فقط الحقول المصرح بها لكل مستخدم بحسب دوره.
  - إخفاء وتجريد الحقول الحساسة (مثل كلمات المرور المجزأة، الأرقام السرية، المفاتيح الخاصة، وبيانات التعريف الداخلية).
- معالجة وإخفاء تفاصيل الأخطاء والرسائل الداخلية (Stack Traces) عن المستخدمين النهائيين.
