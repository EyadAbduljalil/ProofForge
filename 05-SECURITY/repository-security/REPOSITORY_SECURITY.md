# أمان المستودع البرمجي والحوكمة (Repository Security & Governance)

## 1. حماية الفروع وسياسات الدمج (Branch Protection & Merge Policies)
- **حماية الفرع الرئيسي (`main` / `master`)**:
  - حظر الدفع المباشر (Direct Push) أو إعادة الكتابة القسرية للتاريخ (Force Push).
  - اشتراط مراجعة وموافقة نظير واحد على الأقل (Peer Review Approval) قبل الدمج.
  - اشتراط اجتياز كافة اختبارات التكامل المستمر (CI Checks) بنسبة 100% بنجاح ودون أي فشل.
- **التوقيع الرقمي على الإيداعات (Signed Commits)**:
  - اشتراط توقيع كافة الإيداعات باستخدام مفاتيح `GPG` أو `SSH` للتحقق من هوية الكاتب ومنع التزوير.

---

## 2. إدارة الصلاحيات والوصول للمستودع (Access Control)
- تطبيق مبدأ الصلاحيات الدنيا في منح أذونات الكتابة والإدارة للمستودع.
- إلغاء أذونات الحسابات الخاملة أو المنتهية خدماتها فوراً.
- تفعيل المصادقة الثنائية (MFA) إلزامياً لكافة المساهمين في المستودع.

---

## 3. الفحص الأمني التلقائي للشيفرة (SAST & Secret Scanning)
- تشغيل أدوات التحليل الثابت لأمان التطبيقات (Static Application Security Testing - SAST) للكشف عن الأنماط غير الآمنة في الشيفرة قبل الدمج.
- تفعيل الفحص التلقائي ضد تسرب الأسرار والمفاتيح (Secret Scanning) مع خطافات ما قبل الإيداع (`pre-commit hooks`).
- منع إدراج ملفات ثنائية مجهولة المصدر أو ملفات غير نصية غير ضرورية.
