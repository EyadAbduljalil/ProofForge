# أمان معالجة وتخزين الملفات المرفوعة (File Upload Security Standards)

## 1. التحقق الصارم من الملفات المرفوعة
- **التحقق من الامتداد عبر قائمة بيضاء حصراً**: حظر الامتدادات الخطرة والتنفيذية (`.exe`, `.sh`, `.php`, `.jsp`, `.asp`, `.py`, `.bat`, `.cmd`, `.svg` الحاوي على نصوص برمجية).
- **التحقق من التوقيع الثنائي للملف (Magic Bytes / File Signature)**:
  - عدم الاعتماد إطلاقاً على ترويسة `Content-Type` المرسلة من العميل أو امتداد اسم الملف.
  - فحص البايتات الأولى من الملف للتأكد من مطابقتها لنوع الملف الحقيقي المصرح به.
- **تقييد الحجم الأقصى وتحديد الحصص**:
  - فرض حد أقصى لحجم الملف المرفوع على مستوى بوابة الاتصال (Proxy/Gateway) ومستوى خادم التطبيق لمنع هجمات استنزاف الذاكرة والمساحة (DoS).

---

## 2. تخزين وتسمية الملفات بأمان (Secure Storage & Renaming)
- **إعادة تسمية الملفات عشوائياً**: توليد اسم فريد عشوائي للملف (`UUIDv4` + الامتداد المصرح به) وتخزين الاسم الأصلي في قاعدة البيانات فقط كبيانات وصفية.
- **تخزين الملفات خارج جذر خادم الويب (Outside Web Root)**:
  - تخزين الملفات في حاويات تخزين كائنية مخصصة (S3 / GCS / Azure Blob) أو في مسارات لا يمكن الوصول إليها مباشرة عبر خادم الويب.
  - إلغاء أذونات التنفيذ (`noexec`) على مجلدات التخزين المحلي للملفات.

---

## 3. تقديم الملفات للمستخدمين والفحص المضاد للبرمجيات الخبيثة
- **إرجاع ترويسات الأمان أثناء التنزيل**:
  - ضبط `Content-Disposition: attachment; filename="safe_name.ext"`.
  - ضبط `X-Content-Type-Options: nosniff`.
  - ضبط ترويسة `Content-Type` الصحيحة بدقة وتجنب `text/html` للملفات غير النصية.
- **الفحص الأمني المتزامن**: فحص الملفات المرفوعة عبر محركات الكشف عن الفيروسات والبرمجيات الخبيثة قبل إتاحتها للمستخدمين الآخرين.
