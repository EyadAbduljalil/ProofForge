## 2. التحليل الفني المفصل لكل مكتشف

### SEC-REAL-01: ثغرة الفتح الافتراضي في حارس الملكية (`ownership-guard.js`)
- **الملف المصدري:** `packages/security/ownership-guard.js`
- **التحليل في الكود:** كان السطر التالي يعتمد على وجود `ownerId`:
  ```javascript
  const ownerId = resource.user_id || resource.userId || resource.owner_id;
  if (ownerId && String(ownerId) !== String(user.id)) { throw err; }
  return true;
  ```
  عندما يكون المورد مجرداً (مثلاً `{ id: 'res_1' }`) بدون هذه الحقول، كانت القيمة تصبح `undefined`، مما يؤدي لتخطي الرمي وإرجاع `true` مباشرة!
- **إعادة الإنتاج:** تم اختبار تمرير كائن غير معنون بمستخدم ونجح في العبور.
- **التصحيح المنجز:** فرض رفض قاطع: إذا لم يتوفر معرف للمالك ولم يُحدد خيار الوصول العام `options.allowPublic: true`، يتم رمي استثناء أمني فوري برمز `403 Forbidden`.

### SEC-REAL-02: ضعف استنزاف الذاكرة في محدد المعدل (`rate-limit.js`)
- **الملف المصدري:** `packages/security/rate-limit.js`
- **التحليل في الكود:** كان محدد المعدل يحتفظ بكافة المفاتيح عبر `this.hits = new Map()` دون وضع سقف للمفاتيح ودون إخلاء المفاتيح منتهية الصلاحية.
- **الأثر المحتمل:** إمكانية شن هجوم إغراق بعناوين مزورة يؤدي إلى نفاد ذاكرة العملية (OOM DoS).
- **التصحيح المنجز:** إضافة سقف تخزين `maxKeys: 10000`، وتنظيف دوري للمفاتيح التي انقضت مدة نافذتها الزمنية، وإخلاء فوري لأقدم المفاتيح في حال تجاوز السقف.

### SEC-REAL-03: ثغرة تساهل فحص الأدوات في الذكاء الاصطناعي (`ai-security-guard.js`)
- **الملف المصدري:** `packages/security/ai-security-guard.js`
- **التحليل في الكود:** كان فحص الصلاحيات الإدارية للأدوات يعتمد فقط على بادئة الاسم:
  ```javascript
  if (toolName.startsWith('admin_') && user.role !== 'admin') { ... }
  ```
  الأدوات ذات التأثير العالي التي لا تبدأ بـ `admin_` (مثل `delete_database` أو `transfer_funds`) كانت تمر دون فحص رتبة المدير.
- **التصحيح المنجز:** إدراج فحص صارم للأدوات المصنفة كحرجة وحظرها افتراضياً لغير المديرين.

### SEC-REAL-05: فحص دعوى الحاجة لـ Redis و Vault في WebForge
- **التصنيف:** `FALSE_POSITIVE` / `TARGET_PROJECT_REQUIREMENT`.
- **التبرير الفني المعماري:** وفقاً لميثاق الهوية المعمارية في القسم 2، WebForge OS هو **AI Engineering Rulebook & Quality Framework** محايد للتقنيات (Stack-Agnostic)، ويُحظر عليه احتواء بيئات تشغيل إنتاجية (Runtime: FORBIDDEN). إلزام المنظومة بتشغيل Redis أو Vault محلياً يعد خرقاً لحدودها المعمارية. إن توفير القواعد، والمخططات، والمحولات (Adapters) التي تلزم المشاريع المستهدفة باستخدام Redis/Vault هو السلوك المعماري الصحيح.
