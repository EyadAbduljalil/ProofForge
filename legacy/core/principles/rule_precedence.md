# نظام أولوية القواعد (Rule Precedence System)

## 1. الهيكل الهرمي للأولويات

عند حدوث أي تعارض بين المتطلبات، يجب حل التعارض وفقاً لسلم الأولويات الإلزامي التالي بشكل صارم:

```text
P0 — الأمن والحماية وصحة النظام (Security / Safety / Correctness)
P1 — متطلبات المشروع الصريحة (Explicit Project Requirements)
P2 — القواعد الأساسية للمستودع (Core Repository Rules)
P3 — قواعد النطاق التخصصي (Domain Rules: Ecommerce, SaaS, LMS...)
P4 — قواعد نظام التصميم والواجهات (Design System & UI/UX Rules)
P5 — معايير وأعراف إطار العمل (Framework Conventions)
P6 — الإعدادات الافتراضية للمنصة (Platform Defaults)
P7 — اقتراحات الذكاء الاصطناعي العامة (AI Suggestions)
```

## 2. قواعد فض النزاع والتعارض (Conflict Resolution)
1. لا يجوز لأي قاعدة ذات أولوية منخفضة (مثل P4 أو P5) كسر أو تجاوز قاعدة ذات أولوية أعلى (مثل P0 أو P1).
2. إذا تعارضت ميزة بصرية أو تجربة مستخدم مع أمان التطبيق (P0)، يُلغى السلوك البصري فوراً ويُعتمد الخيار الآمن.
3. إذا فرضت منصة الذكاء الاصطناعي (P7) حلاً عاماً يتعارض مع قواعد المستودع (P2)، تُلغى مخرجات الذكاء الاصطناعي وتُطبق قواعد المستودع بالكامل.
4. يجب توثيق أي قرار ناتج عن حل تعارض داخل سجل القرارات المعمارية (ADR).
