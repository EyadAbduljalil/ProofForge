# قواعد الواجهة الأمامية (Frontend Engineering Rules)

## 1. الهيكلية والمكونات
- بناء مكونات معيارية صغيرة ومستقلة (Atomic & Modular Components).
- فصل الحالة المعقدة ومنطق الاتصال بالخادم داخل خطافات مخصصة (Custom Hooks / Services).
- تجنب تكرار المنطق (DRY) والالتزام بنظام تصميم موحد للمشروع.

## 2. الحالات الشاملة لواجهة المستخدم (UI State Completeness)
يجب معالجة كافة الحالات الممكنة لكل مكون يتعامل مع البيانات:
1. **حالة النجاح (Success State)**: عرض البيانات بالشكل المطلوب مع مراعاة الهيكل البصري.
2. **حالة التحميل (Loading State)**: استخدام هياكل التحميل التكيفية (Skeleton Loaders) أو مؤشرات تحميل غير مزعجة ومنع وميض الشاشة.
3. **حالة الفراغ (Empty State)**: تقديم رسائل واضحة وموجهة تشرح سبب غياب البيانات مع زر إجراء مباشر (Call to Action).
4. **حالة الخطأ (Error State)**: رسالة خطأ واضحة ومفهومة للمستخدم مع خيار إعادة المحاولة (Retry Action) دون إظهار أخطاء الخادم التقنية.
5. **حالة الفشل الجزئي (Partial Failure)**: السماح للمستخدم برؤية الجزء المتاح من البيانات مع تنبيهه للأجزاء غير المتاحة.

## 3. النماذج وإدخال البيانات (Forms & User Input)
- تعطيل أزرار الإرسال أثناء المعالجة لمنع تكرار الإرسال (Prevent Double Submission).
- تقديم تغذية راجعة فورية وواضحة للأخطاء الميدانية بالقرب من الحقل المتأثر.
- إدارة التركيز (Focus Management) ونقل التركيز تلقائياً إلى أول حقل يحتوي على خطأ عند فشل الإرسال.

## 4. الأداء واستجابة الواجهة
- تحسين تحميل الصور والموارد باستخدام التحميل الكسول (Lazy Loading) والأنماط الحديثة (WebP, AVIF).
- تقسيم الكود (Code Splitting) للواجهات والمسارات غير المستخدمة فورا.
- تفادي إعادة التصيير غير الضرورية (Unnecessary Re-renders).
