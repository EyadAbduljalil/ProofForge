# بوابات الجودة الهندسية الإلزامية (12 Engineering Quality Gates)

## 1. التعريف بنظام بوابات الجودة
يُحظر الإعلان عن اكتمال أي ميزة أو إطلاق أي مشروع دون اجتياز بوابات الجودة بالترتيب التالي:

\`\`\`text
[Gate 1: Build] ──► [Gate 2: Type Safety] ──► [Gate 3: Lint & Format] ──► [Gate 4: Unit Tests]
       │
       ▼
[Gate 5: Integration Tests] ──► [Gate 6: E2E Browser Flows] ──► [Gate 7: Visual QA] ──► [Gate 8: Responsive QA]
       │
       ▼
[Gate 9: Accessibility A11y] ──► [Gate 10: Security ASVS] ──► [Gate 11: Performance CWV] ──► [Gate 12: Production Readiness]
\`\`\`

## 2. تفاصيل بوابات الجودة
- **Gate 1 — سلامة البناء (Build)**: نجاح بناء المشروع وخلو مخرجات الحزم من الأخطاء.
- **Gate 2 — أمان الأنواع (Type Safety)**: اجتياز فحص مترجم TypeScript دون أخطاء \`tsc --noEmit\`.
- **Gate 3 — الفحص الساكن والتنسيق (Lint & Format)**: التوافق مع معايير الكود المعتمدة.
- **Gate 4 — اختبارات الوحدة (Unit Tests)**: تغطية 100% لمنطق الحسابات والتحقق.
- **Gate 5 — اختبارات التكامل (Integration Tests)**: فحص مسارات الـ API والخدمات وقاعدة البيانات.
- **Gate 6 — اختبارات المتصفح الشاملة (E2E Browser)**: اجتياز تدفقات المستخدم الحرجة عبر Playwright.
- **Gate 7 — الجودة البصرية (Visual QA)**: فحص واجهات المستخدم وخلوها من الانتكاسات البصرية والابتذال.
- **Gate 8 — التجاوب والشاشات (Responsive QA)**: اختبار الواجهات على شاشات الهواتف والأجهزة اللوحية والحواسيب.
- **Gate 9 — إمكانية الوصول (Accessibility)**: التوافق مع معايير WCAG 2.2 AA ودعم لوحة المفاتيح.
- **Gate 10 — الأمان السيبراني (Security ASVS)**: مطابقة متطلبات OWASP ASVS وفحص الثغرات الساكنة والديناميكية.
- **Gate 11 — الأداء والسرعة (Performance & CWV)**: تحقيق LCP < 2.5s و INP < 200ms واستقرار CLS < 0.1.
- **Gate 12 — الجاهزية للإنتاج (Production Readiness)**: تكوين متغيرات الإنتاج المشفرة ونقاط الفحص الصحي \`/healthz\`.

## 3. حظر اللون الأخضر الزائف (No Green-by-Default Rule)
يُحظر تعديل الإعدادات أو تعطيل الاختبارات أو إخفاء أخطاء الكونسول أو رفع العتبات لمجرد جعل المؤشر أخضر دون معالجة الخلل الفعلي في الكود.
