# دورة التصحيح التلقائي وتحديد السبب الجذري (Autonomous Fix Loop & Root-Cause Analysis)

## 1. بروتوكول حلقة التصحيح الآلية
عند فشل أي فحص أو اختبار:

\`\`\`text
فشل الفحص (FAIL)
       ↓
جمع الأدلة وسجلات الآثار (Collect Evidence & Traces)
       ↓
تحليل وتحديد السبب الجذري الفعلي (Identify Root Cause)
       ↓
تنفيذ الإصلاح الهندسي في الطبقة المعنية (Implement Fix)
       ↓
إعادة تشغيل الفحص البؤري المتأثر (Run Focused Test)
       ↓
تشغيل الفحوصات ذات الصلة وتحليل أثر التغيير (Impact Analysis)
       ↓
تشغيل حزمة اختبارات التراجع الشاملة (Run Full Regression Suite)
\`\`\`

## 2. متطلب السبب الجذري (Root-Cause Requirement)
يُحظر معالجة العرض السطحي للخطأ كأنه السبب الجذري.
- **مثال**: عند فشل زر في الاستجابة للنقر:
  - يُمنع إضافة معالج نقر إضافي أو تأخير زمني عشوائي (`setTimeout`).
  - يجب تتبع المسار بالترتيب:
    \`\`\`text
    واجهة المستخدم (UI) ──► الحدث (Event) ──► الحالة (State) ──► واجهة الـ API ──► الخادم (Backend) ──► قاعدة البيانات (Database)
    \`\`\`
  - إصلاح الطبقة المكسورة فعلياً.

## 3. تصنيف شدة الأعطال (Failure Severity Classification)
- **BLOCKER**: عطل يعطل مسار البناء أو يعيق تشغيل النظام بالكامل.
- **CRITICAL**: ثغرة أمنية تسمح بتسريب البيانات أو تجاوز الصلاحيات أو تلف السجلات المالية.
- **HIGH**: فشل في تدفق مستخدم رئيسي (مثل تعطل الدفع أو التسجيل أو إنشاء الطلب).
- **MEDIUM**: خلل في ميزة غير حرجة أو عدم دقة في التجاوب في نقطة توقف محددة.
- **LOW**: ملاحظة شكلية أو تحسين في التنسيق لا يؤثر على الاستخدام.
- **INFO**: توثيق أو مقترح تحسين مستقبلي.
