# API-VERSION-001: إلزامية إصدارات واجهات برمجة التطبيقات والتوافقية العكسية

## 1. المتطلب الإلزامي (Requirement)
يجب أن تحتوي كافة مسارات واجهات برمجة التطبيقات العامة على معرّف إصدار صريح في المسار (مثل `/api/v1/...`)، ويُحظر إدخال أي تغييرات كاسرة للتوافقية العكسية (Breaking Changes) على إصدار قائم دون رفع رقم الإصدار إلى `v2` وتوفير فترة ترحيل وإشعار مسبق.

## 2. مبررات المتطلب والأثر الأمني/الهندسي (Rationale)
تغيير بنية الاستجابات أو حذف حقول قائمة دون رفع الإصدار يسبب توقف مفاجئ للتطبيقات العميلة وتلف في عمليات التكامل الخارجي.

## 3. الأنماط المعيبة (Bad Patterns)
```javascript
// مسارات عامة بلا إصدار محدد
app.use('/api/users', usersRouter);
```

## 4. الأنماط السليمة المعتمدة (Good Patterns)
```javascript
// مسار موضح بإصدار دلالي
app.use('/api/v1/users', v1UsersRouter);
```

## 5. آلية الفحص والتحقق الآلي (Validation Check)
- فحص مسارات نقاط النهاية والتأكد من مطابقتها للنمط `/api/v[0-9]+/`.

## 6. الدليل المطلوب للإثبات (Required Evidence)
- تقرير مراجعة مسارات الـ API يثبت شمولها لأرقام الإصدارات.

## 7. خطوات الإصلاح والمعالجة (Remediation)
1. إعادة توجيه المسارات القديمة وبناء هيكل الإصدارات `/v1/`.

## 8. الاستثناءات المسموحة (Allowed Exceptions)
نقاط النهاية الداخلية الخاصة جداً وغير المعرضة للجمهور (مثل `/healthz`).
