# الدليل الهندسي: معيار القياس A/B، عقود الأدلة المستقلة، وبوابة الاعتماد المغلقة عند الإخفاق

## 1. معيار مقارنة كفاءة الوكلاء A/B الحقيقي (Genuine Agent A/B Benchmark)

### 1.1 المعمارية التجريبية المستقلة
يقوم معيار `AgentEffectivenessBenchmark` على مقارنة علمية زوجية مستقلة (Independent Paired Trials) بين شرطين متطابقين في كافة المتغيرات ما عدا طبقة حوكمة ProofForge:
- **الشرط الضابط (Condition A - Control)**: استدعاء مشغل الوكيل المعتمد الفعلي مع تعطيل مهارات وقواعد ProofForge بالكامل، مع تزويده بنفس المهمة ومواصفات النموذج والحدود البيئية.
- **الشرط المعالج (Condition B - Treatment)**: استدعاء نفس مشغل الوكيل مع تفعيل مهارات ProofForge وعقود الأدلة والتحقق الحتمي.

### 1.2 التمييز الصارم بين دفاع المثبتات وقياس الوكلاء
- **معيار دفاع المثبتات (`FixtureDefenseBenchmark`)**: يفحص كوداً ونماذج عيوب ثابتة (Flawed Fixtures) على القرص للتأكد من قدرة أدوات الفحص على رصد العيوب واكتشافها.
- **معيار كفاءة الوكلاء (`AgentEffectivenessBenchmark`)**: يقيس جلسات تفاعلية حقيقية مع وكيل ذكاء اصطناعي.
- **قاعدة حظر الخلط**: يُحظر قطعياً وراثياً أو إجرائياً تصنيف نتائج فحص المثبتات على أنها دليل تفوق لوكيل الذكاء الاصطناعي.
- في غياب مشغل وكيل تفاعلي مزدوج، يُسجل المعيار فوراً وبوضوح:
  `status: 'AGENT_AB_BENCHMARK_UNAVAILABLE'` أو `status: 'NOT_RUN'` مع حظر تحويله إلى `PASS`.

## 2. عقد الأدلة الحتمي والتحقق المستقل (Strict Evidence Contract)

### 2.1 الفصل بين مسؤوليات المنتج والمدقق (Producer vs. Verifier Separation)
- **المنتج (Producer)**: ينفذ المهمة، يولد المخرجات، ويسجل بيانات التنفيذ. لا يملك سلطة تزكية عمله أو إصدار نتيجة التحقق النهائية.
- **المدقق (Verifier)**: يقرأ المخرجات بشكل مستقل، يعيد احتساب التجزئة المشفرة SHA-256 للملفات على القرص، يفحص مطابقة معرف الفحص الدقيق، ويحدد حالة التحقق.
- **حظر التزكية الذاتية**: إذا تطابقت هوية المنتج مع هوية المدقق، يرفض النظام الدليل فوراً برمز `FAIL-CLOSED`.

### 2.2 المطابقة التامة لمُعرف الفحص (Exact Check ID Matching)
- حظر مطابقة البوادئ (Prefix Matching) أو الكلمات المفتاحية الجزئية (مثلاً: `SEC-01` لا تطابق `SEC-010`).
- المطابقة التامة الحرفية مع الفحص الكنسي المسجل في `CANONICAL_EVIDENCE_MAP`.

### 2.3 متطلبات المخرجات المادية وبصمة المصدر (Artifacts & Provenance)
- الفحوصات التي تشترط مخرجاً مادياً يُحظر تمريرها بمسار فارغ `artifactPath: null`.
- إعادة قراءة وحساب تجزئة الملف ومطابقتها لمنع أي تعديل أو تلاعب لاحق.
- ربط الدليل بـ Git Commit SHA الدقيق ومُعرف التنفيذ وطابع زمني رتيب.

## 3. بوابة الاعتماد الصارمة والمغلقة عند الإخفاق (Fail-Closed Release Gate)

### 3.1 الاستخراج الإلزامي لـ Git HEAD
تستخرج البوابة التجزئة الفعلية لـ HEAD من مستودع Git مباشرة وتتحقق من كونه مجلد المستودع الجذري الفعلي (`--show-toplevel`). في حال تعذر الاستخراج أو كان الرمز مشوهاً، تسقط البوابة فوراً برمز:
- `RELEASE_HEAD_UNRESOLVED`
- `RELEASE_HEAD_INVALID`

### 3.2 المطابقة التامة مع ملف الأدلة (Evidence-to-HEAD Binding)
- مطابقة تامة بطول 40 محرف ست عشري بين HEAD الحالي وملف `docs/release/FINAL_TEST_EVIDENCE.json`.
- في حال وجود أي اختلاف أو استخدام رمز بديل (Placeholder)، تُرفض العملية فوراً برمز `RELEASE_COMMIT_MISMATCH`.

### 3.3 مصفوفة رموز الإخفاق الآلية (Deterministic Failure Codes)
- `RELEASE_HEAD_UNRESOLVED`: تعذر استخراج Git HEAD.
- `RELEASE_HEAD_INVALID`: تجزئة Git HEAD مشوهة أو غير صالحة.
- `RELEASE_EVIDENCE_MISSING`: ملف الأدلة مفقود.
- `RELEASE_EVIDENCE_INVALID`: ملف الأدلة تالف أو غير صالح.
- `RELEASE_COMMIT_MISMATCH`: تعارض تجزئة الدليل مع HEAD الحالي.
- `RELEASE_REQUIRED_CHECK_MISSING`: غياب فحص أو مجموعة إلزامية.
- `RELEASE_REQUIRED_CHECK_FAILED`: وجود فحوصات فاشلة في إحدى المجموعات.
- `RELEASE_INDEPENDENT_VERIFICATION_MISSING`: محاولة تزييف حالة اختبارات غير منفذة كـ PASS.
