# 🔄 ميثاق التنسيق وتدفق العمل بين المهارات (Cross-Skill Coordination & Workflow Guide)
## ProofForge V2 — Autonomous Multi-Skill Orchestration Framework

---

## 1. الفلسفة المعمارية للتنسيق الهندسي (Orchestration Philosophy)

تعتمد منظومة ProofForge على نموذج **المهارات المتخصصة غير المتداخلة** الموجهة بواسطة **Google Antigravity**. لتجنب تكرار العمل أو تضارب التعليمات، تخضع كافة المهارات لدورة حياة هندسية مغلقة مكونة من 10 مراحل حتمية (10-Stage Lifecycle)، حيث تسلّم كل مهارة مخرجاتها كـ "حزم أدلة موثقة" (Evidence Packages) للمهارة اللاحقة.

```
[1. Architecture] ──> [2. Security] ──> [3. Database] ──> [4. Backend/API]
                                                                  │
[8. Production] <── [7. Review/A11y] <── [6. Frontend] <── [5. Design System]
      │
      └──> [9. Testing/Audit] ──> [10. Deployment]
```

---

## 2. المراحل العشر لدورة الحياة الهندسية (The 10-Stage Lifecycle)

### المرحلة 1: التصميم المعماري وحدود النطاق (`architecture`)
* **المدخلات:** فكرة التطبيق، متطلبات العمل، قيود النطاق.
* **المسؤوليات:** تحديد نمط البنية (Clean Architecture / Hexagonal)، عزل النطاقات، رسم حدود المستأجرين (Tenancy Model)، وتوليد سجل القرارات المعمارية (ADR).
* **المخرجات المسلمة:** `docs/adr/`, `contracts/domain-invariants.json`.

### المرحلة 2: نمذجة التهديدات والحوكمة الأمنية (`security`)
* **المدخلات:** مخططات المرحلة 1، مسارات تدفق البيانات.
* **المسؤوليات:** تحليل مساحة الهجوم، فرض متطلبات OWASP ASVS L2، تشفير البيانات أثناء النقل والسكون، فرض سياسات عدم الثقة المطلقة بالعميل (Zero-Trust).
* **المخرجات المسلمة:** `security-threat-model.json`, `auth-matrix.json`.

### المرحلة 3: هندسة البيانات والنمذجة الصارمة (`database`)
* **المدخلات:** مخططات المجال والسياسات الأمنية.
* **المسؤوليات:** تصميم جداول البيانات العلائقية، فرض مفاتيح العزل (`tenant_id`)، مؤشرات الأداء، وعمليات التعديل الذرية (ACID Transactions).
* **المخرجات المسلمة:** مسودات الترحيل `migrations/`, نماذج التحقق والتكامل.

### المرحلة 4: هندسة الواجهات الخلفية وواجهات البرمجة (`backend` + `api`)
* **المدخلات:** مواصفات قاعدة البيانات والوثائق المعمارية.
* **المسؤوليات:** بناء نقاط النهاية REST/GraphQL، غلاف الاستجابة الموحد `ApiResponse`، مصادقة JWT، حماية الـ CSRF/CORS، ومحددات السرعة (Rate Limiting).
* **المخرجات المسلمة:** مواصفة `openapi.json`, موجهات Express/Node.js الآمنة.

### المرحلة 5: نظام التصميم والهوية البصرية (`design-system` + `anti-slop`)
* **المدخلات:** متطلبات تجربة المستخدم، سمات البراند.
* **المسؤوليات:** تعريف الرموز التصميمية (Design Tokens)، مقياس المسافات 4px/8px، نسب التباين WCAG AAA، حظر القوالب المشوهة والتدرجات العشوائية.
* **المخرجات المسلمة:** `tokens.css`, توجيهات الطباعة والألوان.

### المرحلة 6: هندسة الواجهات الأمامية والذكاء الكامل (`frontend` + `fullstack` + `responsive` + `rtl`)
* **المدخلات:** واجهات API وعقود التصميم ومصفوفة الرموز.
* **المسؤوليات:** بناء شاشات تفاعلية خالية من تسريب الحالات، توافق كامل مع الهواتف الذكية (320px إلى 4K)، دعم الاتجاهين RTL/LTR، وحالات الآلة الحتمية (Idle, Loading, Error, Empty, Success).
* **المخرجات المسلمة:** مكونات الواجهة، صفحات التطبيق، معالجات النماذج.

### المرحلة 7: فحص الكود وإمكانية الوصول (`code-review` + `accessibility` + `anti-laziness`)
* **المدخلات:** كامل الكود المكتوب في الواجهات والخلفية.
* **المسؤوليات:** مراجعة هجومية للكود، حظر الثغرات الأمنية والكود الكسول (`// TODO`)، فحص ملاءمة قارئات الشاشة (ARIA)، والتنقل عبر لوحة المفاتيح.
* **المخرجات المسلمة:** تقرير المراجعة `review-findings.json`.

### المرحلة 8: فحص الأداء وتجربة المستخدم المتقدمة (`performance` + `motion` + `taste-craft`)
* **المدخلات:** التطبيق المكتمل بعد المراجعة.
* **المسؤوليات:** قياس مؤشرات Core Web Vitals (LCP, INP, CLS)، تحسين استهلاك المعالج والذاكرة، إضافة تغذية حسية للأزرار (`:active`)، وحركات سلسة 60fps عبر GPU.
* **المخرجات المسلمة:** تقرير قياس الأداء والأصول المحسنة.

### المرحلة 9: ضمان الجودة والتدقيق الشامل (`testing` + `project-audit` + `production-readiness`)
* **المدخلات:** كامل المنظومة البرمجية وقاعدة البيانات.
* **المسؤوليات:** تشغيل اختبارات الوحدة والتكامل و E2E، فحص مجسات الجاهزية (`/healthz`, `/readyz`)، التحقق من عدم وجود مفاتيح مسربة في الكود، وتدقيق 14 معياراً آلياً.
* **المخرجات المسلمة:** تقرير التدقيق العام `project-audit-report.json`.

### المرحلة 10: النشر السحابي والبنية التحتية (`deployment`)
* **المدخلات:** حزمة التطبيق المدققة والمختبرة بالكامل.
* **المسؤوليات:** بناء صور Docker متعددة المراحل غير جذرية (Non-root user)، إعداد خطوط CI/CD القابلة للتكرار، وتوثيق بيئة الإنتاج.
* **المخرجات المسلمة:** `Dockerfile`, `docker-compose.yml`, خط أنابيب النشر.

## 3. مصفوفة تفويض وتمرير البيانات (Context & Artifact Passing Protocol)

| من مهارة | إلى مهارة | الحزمة الممررة (Payload) | وسيلة التحقق الحتمية |
|---|---|---|---|
| `architecture` | `backend` / `database` | مخططات الحدود وكيانات النطاق | تدقيق النطاق عبر `verify_architecture.js` |
| `security` | `api` / `backend` | مصفوفة التحقق من الصلاحيات وRBAC | فحص ترويسات الأمان عبر `verify_backend.js` |
| `database` | `backend` | نماذج الجداول ومفاتيح المستأجرين | فحص المعاملات الذرية عبر `verify_database.js` |
| `api` | `frontend` | مواصفة OpenAPI وعقود الاستجابة | فحص مطابقة Envelope عبر `verify_api.js` |
| `design-system` | `frontend` | رموز التصميم CSS Tokens والتباين | فحص الرموز عبر `verify_tokens.js` |
| `frontend` | `accessibility` | عناصر HTML وخصائص ARIA | فحص التوافق عبر `audit_a11y.js` |
| `all-skills` | `project-audit` | كافة ملفات المستودع والأدلة | التدقيق المتكامل عبر `run_audit.js` |

## 4. ميثاق حظر التداخل (Anti-Overlap Principles)

1. **السيادة التخصصية:** لا تتدخل مهارة الـ `frontend` في هندسة استعلامات SQL، بل تفوض ذلك لمهارة `database`.
2. **عزل الحوكمة الأمنية:** لا يجوز تجاوز المتطلبات الأمنية المحددة في مهارة `security` تحت مبرر سهولة الاستخدام أو سرعة الإنجاز.
3. **عقد الدليل الصارم (Evidence Contract):** لا تُقبل أي مهمة كمنتهية دون استخراج مخرجات رقمية فاحصة وإثبات مادي لا يقبل التخمين أو الادعاءات غير الموثقة.
