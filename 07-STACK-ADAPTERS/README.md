# طبقة محولات المكدس التقني (WebForge OS Stack Adapters Layer)

## 1. النطاق والهدف المعماري
تمثل طبقة `07-STACK-ADAPTERS/` جسر التفسير والترجمة التقنية في نظام WebForge OS. تهدف هذه الطبقة إلى ترجمة متطلبات وقواعد WebForge الكنسية (الواردة في `01-KNOWLEDGE`, `03-DESIGN`, `04-ENGINEERING`, `05-SECURITY`, `06-VALIDATORS`) إلى أنماط وأمثلة وقيود تفسيرية مخصصة للتقنيات والمكدسات البرمجية التي يختارها المشروع المستهدف.

---

## 2. المبدأ المعماري الحاكم
> **المشروع يختار مكدسه التقني، و WebForge يكتشف، ينمذج، يطابق، يكيف، ويتحقق.**

محول المكدس هو **طبقة تفسير ومعرفة تصريحية** وليس طبقة سلطة؛ ولا يُعد إطار عمل تنفيذي أو حزمة تشغيلية ولا يفرض أي تقنية بعينها على المشروع.

---

## 3. الهيكل المعرفي لمجلد محولات المكدس

```
07-STACK-ADAPTERS/
├── README.md                           # دليل النطاق والهيكل المعماري
├── STACK_ADAPTER_CONTRACT.md           # العقد المعياري لتعريف محولات المكدس
├── STACK_PROFILE_SCHEMA.md             # مخطط ملف تعريف المكدس التقني للمشروع
├── CAPABILITY_MAPPING_MODEL.md         # نموذج مطابقة قدرات المكدس مع القواعد
├── COMPATIBILITY_MODEL.md              # نموذج ومستويات التوافقية التقنية
├── ADAPTER_APPLICABILITY.md            # محددات ومعايير انطباق المحولات
├── ADAPTER_CONFLICTS.md                # نموذج حل تعارضات المحولات والقواعد الكنسية
├── ADAPTER_SECURITY.md                 # أمان المحولات ومكافحة حقن التوجيهات
├── ADAPTER_VERSIONING.md               # سياسات إدارة إصدارات التقنيات والمحولات
└── ADAPTER_REGISTRY.md                 # السجل المركزي للمحولات المعتمدة
```

---

## 4. هرمية السلطة وحل التعارضات
في حال حدوث أي تعارض بين إرشادات محول المكدس والقواعد الكنسية لـ WebForge:
1. **الضوابط الأمنية والسلامة**: تسود دائماً.
2. **المتطلبات المشروعة الصريحة للمشروع**: تسود على التفضيلات العامة.
3. **القواعد الكنسية لـ WebForge**: تسود على إرشادات المحولات.
4. **إرشادات محول المكدس والقوالب**: تأتي في المرتبة التفسيرية التابعة.
