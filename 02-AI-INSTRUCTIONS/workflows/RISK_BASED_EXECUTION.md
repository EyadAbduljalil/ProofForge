# مسار التنفيذ القائم على تقييم المخاطر (Risk-Based Execution Workflow)

## المعرّف: `WFL-RISK-EXECUTION-001`
## الحالة: `ACTIVE`

---

## 1. الغرض
موازنة الأتمتة والسرعة مع الانضباط الأمني، بتحديد مستوى الاستقلالية والتحقق بناءً على درجة خطورة العملية البرمجية وحجم أثرها المحتمل.

---

## 2. مصفوفة مستويات المخاطر والاستقلالية

| مستوى الخطر | العمليات التمثيلية | مستوى الاستقلالية الممنوح | متطلبات الحماية والتحقق |
| :--- | :--- | :--- | :--- |
| **منخفض (LOW)** | قراءة ملفات، فحص الكود، كتابة اختبارات، تعديل توثيق، ضبط تنسيقات CSS غير كاسرة. | استقلالية كاملة | فحص نحوي واختبارات قياسية. |
| **متوسط (MEDIUM)** | إضافة مسار API جديد، إضافة مكون واجهة تفاعلي، تعديل منطق عمليات غير حرج. | استقلالية مع نقطة استعادة | إنشاء نقطة استعادة + تشغيل حزمة الاختبارات الشاملة. |
| **عالي (HIGH)** | تعديل متحكمات المصادقة، تعديل الجداول وقواعد البيانات، ترقية مكتبات رئيسية. | مقيد بحواجز أمان | فحص أمني مكثف + فحص انحدار شامل + منع التراجع الصامت. |
| **حرج (CRITICAL)** | عمليات الحذف التدميرية، تعديل البنية التحتية الإنتاجية، تدوير المفاتيح الأساسية. | يتطلب موافقة صريحة | حظر التنفيذ التلقائي + طلب تفويض بشري صريح (Human Gate). |

---

## 3. مبدأ التراجع الآمن
لكل عملية مصنفة كـ `MEDIUM` أو `HIGH`، يجب التأكد من إمكانية التراجع الذري التام (Byte-level Git Rollback) قبل إجراء التعديل.
