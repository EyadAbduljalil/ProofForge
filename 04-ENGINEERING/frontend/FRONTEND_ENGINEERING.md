# هندسة الواجهات الأمامية والحدود غير الموثوقة
## Frontend Engineering, State Boundaries & Client Trust Limits

---

## 1. القاعدة الذهبية للواجهات الأمامية (The Client-Side Trust Boundary)

> **الواجهة الأمامية وبيئة العميل غير موثوقة أمنياً بشكل كامل (CLIENT IS UNTRUSTED).**
> التحقق من صحة المدخلات في المتصفح هو ميزة لتحسين تجربة المستخدم وسرعة التغذية الراجعة فقط، وليس ضابطاً أمنياً (Client validation is NOT a security control).

---

## 2. أفضل الممارسات الهندسية للواجهات الأمامية

1. **إدارة الحالة النظيفة (State Ownership)**:
   - فصل حالة الخادم (Server State مثل استجابات الـ API) عن الحالة المحلية للواجهة (UI State مثل النوافذ المفتوحة).
   - منع الطفرات المباشرة غير القابلة للتتبع في كائنات الحالة.
2. **عزل الآثار الجانبية والتحديثات المتفائلة (Optimistic Updates)**:
   - دعم التحديثات المتفائلة لتحسين السرعة مع توفير آلية تراجع حتمية (Rollback) عند فشل استجابة الخادم.
3. **معالجة حالات التحميل والأخطاء والفراغ**:
   - لا تعتمد الواجهة على المسار المثالي فقط، بل توفر شاشات تحميل هيكلية (Skeletons) ورسائل خطأ قابلة للتنفيذ.
