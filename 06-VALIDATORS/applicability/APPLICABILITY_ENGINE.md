# نموذج ومحرك تحديد انطباق القواعد (Applicability Engine)

## 1. مبادئ تقييم الانطباق (Applicability Principles)
- **لا انطباق تلقائي**: لا تُعتبر القاعدة منطبقة على المشروع لمجرد وجودها في الدستور؛ بل يجب استيفاء شروط مسبقة واضحة وموثقة.
- **عدم اعتبار غياب الدليل إثباتاً لعدم الانطباق**: إذا كانت هناك مؤشرات على وجود ميزة (مثل مسارات API أو واجهات دفع) ولكن دون توفر تفاصيل كافية، تُصنف الحالة كـ `INSUFFICIENT_EVIDENCE` بدلاً من افتراض عدم الانطباق.
- **حظر التحايل بحذف الأدلة**: لا يُسمح بتجاوز القواعد الحرجة عبر حذف ملفات التكوين أو تجريد البيانات الوصفية لإظهار عدم الانطباق زيفاً.

---

## 2. معايير تحديد الانطباق (Applicability Criteria)

| معيار الانطباق | أمثلة وشروط التحقق | القواعد المتأثرة |
| :--- | :--- | :--- |
| **طبيعة الواجهة (User Interface)** | وجود ملفات HTML, CSS, React, Vue, Svelte أو أصول العميل | قواعد التصميم وإمكانية الوصول `03-DESIGN` و `ENG-FE-*` |
| **طبقة الخدمات وواجهات البرمجة (API/Backend)** | وجود مسارات خادمة، بروتوكولات REST/GraphQL/gRPC | قواعد واجهات البرمجة والأمان `ENG-API-*`, `SEC-API-*` |
| **طبقة التخزين وقواعد البيانات (Data Layer)** | وجود مخططات جداول، ملفات ترحيل، اتصالات SQL/NoSQL | قواعد قواعد البيانات والحماية `ENG-DB-*`, `SEC-DATA-*` |
| **أنظمة التوثيق والجلسات (Auth/Sessions)** | وجود جداول مستخدمين، نقاط تسجيل الدخول، رموز JWT | قواعد التوثيق والتفويض `SEC-AUTH-*`, `SEC-AUTHZ-*` |
| **المعالجة غير المتزامنة (Queues/Workers)** | وجود وسطاء رسائل، عمال خلفية، طوابير معالجة | قواعد الطوابير والموثوقية `ENG-QUEUE-*`, `ENG-REL-*` |
| **معالجة الملفات المرفوعة (File Uploads)** | وجود مسارات رفع ملفات، معالجة وسائط متعددة | قواعد أمان الملفات `SEC-FILE-*` |

---

## 3. نتائج تقييم الانطباق
- **`APPLICABLE`**: الشروط المسبقة متحققة ويجب تشغيل المدققات المخصصة.
- **`NOT_APPLICABLE`**: الشروط المسبقة غير متحققة صراحة، مع توثيق سبب الاستبعاد في سجل التحقق.
- **`UNKNOWN / INSUFFICIENT_EVIDENCE`**: اشتباه في وجود الميزة مع نقص في البيانات الوصفية، مما يتطلب استكشافاً أعمق ويحظر إغلاق البوابة تلقائياً.
